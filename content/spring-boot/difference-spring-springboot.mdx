₹5 Crore Interview Answer
Question

Why was Spring Boot created?

Excellent Answer (English)

Spring Boot was created to simplify the development experience of Spring Framework applications. Although Spring Framework significantly reduced the complexity of enterprise Java, developers still had to perform repetitive configuration, manage dependency compatibility, configure external application servers, and spend considerable effort on project setup. Spring Boot addressed these challenges by introducing convention over configuration, starter dependencies, auto-configuration, embedded web servers, and production-ready features, while continuing to use the Spring Framework as its underlying runtime.

₹5 Crore Interview Answer
Question

What is the difference between Spring Framework and Spring Boot?

Excellent Answer (English)

Spring Framework is the core enterprise application framework that provides features such as IoC, Dependency Injection, AOP, transaction management, MVC, and bean lifecycle management. Spring Boot is built on top of Spring Framework to simplify application development by reducing repetitive configuration, providing starter dependencies, offering auto-configuration, embedding web servers, and enabling production-ready features such as Actuator. Spring Boot does not replace Spring Framework; instead, it automates common setup tasks while continuing to use Spring Framework as its underlying runtime.

Answer: It allows applications to run as self-contained executable JAR files without requiring a separately installed application server.

Answer: Because Spring Boot simplifies service creation, packaging, deployment, and integration with the broader Spring ecosystem, making it well-suited for cloud-native and microservice architectures.

What happens inside SpringApplication.run()?

Excellent Answer (English)

SpringApplication.run() is the primary bootstrap mechanism provided by Spring Boot. It prepares the application environment, determines the application type, creates the appropriate ApplicationContext, loads configuration sources, refreshes the Spring context, triggers bean creation and dependency injection through the Spring Framework, starts the embedded web server for web applications, and finally makes the application ready to accept requests. While Spring Boot orchestrates the startup process, the underlying IoC container, bean lifecycle, dependency injection, and application infrastructure are still provided by the Spring Framework.
