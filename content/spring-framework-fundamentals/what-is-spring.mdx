Interview Question
Q: Why was Spring introduced when Java already existed?

Excellent Answer (English)

Java is a powerful programming language, but it does not provide a complete enterprise application development ecosystem. Developers had to manually manage object creation, dependency management, transactions, configuration, exception handling, security, and integration. Spring was introduced to solve these enterprise-level challenges by providing Inversion of Control, Dependency Injection, modular architecture, transaction management, and simplified infrastructure, enabling developers to focus primarily on business logic.

Numbered Interview Questions & Answers (Current Topic)
1. What is Spring?

Answer: Spring is a lightweight, open-source, enterprise-grade Java framework that simplifies enterprise application development through features such as IoC, Dependency Injection, transaction management, modular architecture, and integration support.

2. Why was Spring introduced?

Answer: Spring was introduced to overcome the complexity of enterprise Java development, especially the heavy configuration and tight coupling associated with technologies like EJB.

3. Is Spring a programming language?

Answer: No. Spring is a Java framework built on top of the Java language.

4. Why is Spring called lightweight?

Answer: Because it reduces complexity, boilerplate code, and configuration overhead while allowing developers to use only the required modules instead of a heavy enterprise stack.

5. Why is Spring considered enterprise-grade?

Answer: Because it provides features required for large-scale production systems, including dependency management, transaction support, security integration, testing support, scalability, and modular architecture.

5 Crore Interview Explanation

Question: Why did Spring become more popular than EJB?

Strong Answer (English)

Spring gained popularity because it dramatically simplified enterprise Java development. Unlike EJB, which required heavy application servers, extensive XML configuration, multiple interfaces, and container-specific deployment, Spring promoted lightweight architecture, Plain Old Java Objects (POJOs), Inversion of Control, Dependency Injection, modular design, and easier testing. This significantly improved developer productivity, maintainability, and scalability while reducing infrastructure complexity.

Answer: Rod Johnson created the Spring Framework after identifying the complexity of enterprise Java development, particularly with EJB-based applications.

7. Why did Rod Johnson create Spring?

Answer: He wanted to simplify enterprise Java development by reducing configuration complexity, removing unnecessary infrastructure code, and allowing developers to focus on business logic.

8. What was the biggest limitation of EJB?

Answer: EJB introduced heavy configuration, multiple interfaces, container dependency, complex deployment, and difficult testing, making enterprise development slower and more complex.

9. Does Spring replace Java?

Answer: No. Spring is built on top of Java. Java provides the language, while Spring provides the enterprise application framework and infrastructure.

10. What is the core philosophy of Spring?

Answer: Spring's core philosophy is to simplify enterprise application development by managing infrastructure concerns—such as object creation, dependency management, transactions, and configuration—so developers can concentrate on implementing business logic.

5 Crore Interview Answer

Question: What is the difference between a Library and a Framework?

Excellent Answer (English)

A library is a reusable collection of code that is invoked by the application whenever needed. The application remains in control of the execution flow. A framework, on the other hand, provides the application's overall structure and controls the execution flow, invoking application-specific code at predefined extension points. This inversion of control enables consistency, modularity, and easier maintenance in enterprise applications.

Official Definition

A POJO is a regular Java object that is not required to extend framework-specific classes or implement framework-specific interfaces simply to function as a domain object.

Interview Answer (5 Crore Level)

Question: What is a POJO, and why is it important in Spring?

Excellent Answer (English)

A POJO (Plain Old Java Object) is a regular Java class that is not required to extend framework-specific classes or implement framework-specific interfaces merely to represent business data or behavior. Spring promotes POJO-based development to keep business logic independent of infrastructure concerns, improving maintainability, testability, reusability, and flexibility. The Spring IoC container can manage these POJOs as Beans without forcing the business model to depend on the framework.

Question: Explain the architecture of the Spring Framework.

Excellent Answer (English)

Spring follows a modular architecture centered around its Core Container, which consists of the Core, Beans, Context, and Expression Language modules. The Core Container provides dependency injection and bean management. Higher-level modules such as AOP, JDBC, Transaction Management, Web, MVC, Security, and Testing build upon this foundation. This layered, modular design allows developers to include only the required functionality, resulting in loosely coupled, maintainable, scalable, and enterprise-ready applications.

5 Crore Interview Answer
Question

How does Spring manage Beans internally?

Excellent Answer (English)

During startup, Spring performs component scanning and uses reflection to identify candidate classes. It registers metadata for these classes as Bean Definitions inside the container. During context initialization, the IoC container creates bean instances according to those definitions. Singleton-scoped beans are maintained in Spring's internal singleton registry, allowing the same managed instance to be reused throughout the application. When a dependency is required, the container resolves it using bean metadata and injects the appropriate managed bean.

Numbered Interview Questions & Answers
46. Where does Spring store Bean information?

Answer: Spring stores bean metadata as Bean Definitions within the container and maintains managed bean instances separately. Singleton beans are kept in the container's singleton registry.

47. Is a Bean Definition the same as a Bean?

Answer: No. A Bean Definition is metadata describing how to create and manage a bean, while the Bean is the actual runtime object.

48. Why does Spring keep singleton beans?

Answer: Reusing singleton beans reduces unnecessary object creation, improves performance, simplifies dependency management, and provides a shared managed instance where appropriate.

49. How does @Autowired find a Bean?

Answer: The Spring container resolves dependencies using the registered bean metadata, matching the required dependency (primarily by type, and then by qualifiers or other rules if needed) before injecting the managed bean.

50. Does Spring create all beans every time they are requested?

Answer: No. By default, singleton beans are created once during context initialization (unless lazy initialization is configured) and reused. Prototype beans follow a different lifecycle.

5 Crore Interview Answer
Question

Explain Spring Framework from startup until response generation.

Excellent Answer (English)

A Spring Boot application starts when the operating system launches the JVM, which loads the application's main class and invokes the main() method. The main() method calls SpringApplication.run(), which prepares the environment, creates the ApplicationContext, processes configuration classes, performs component scanning, and uses Java Reflection to identify candidate components. Spring registers Bean Definitions, creates and initializes managed beans through the IoC container, performs dependency injection, refreshes the application context, and starts the embedded web server for web applications. Once the application is ready, incoming HTTP requests are accepted by the embedded server, forwarded to the DispatcherServlet, routed to the appropriate controller, delegated to the service and repository layers, executed against the database, and finally returned to the client as an HTTP response.

Numbered Interview Questions & Answers
51. What starts first: Spring or JVM?

Answer: The JVM starts first. Spring runs as application code inside the JVM.

52. Who calls the main() method?

Answer: The JVM invokes the main() method after loading the application's main class.

53. What is the role of SpringApplication.run()?

Answer: It orchestrates the Spring Boot startup process by preparing the environment, creating the ApplicationContext, refreshing the container, and starting the embedded server when applicable.

54. When does Component Scanning occur?

Answer: During application startup, after the container begins processing configuration but before managed beans are fully initialized.

55. What processes an HTTP request in Spring MVC?

Answer: The embedded server receives the request, the DispatcherServlet acts as the front controller, routes it to the appropriate controller, and coordinates the response flow through the service and repository layers.
