1. LinkedList — Introduction

What is a LinkedList?

LinkedList = Doubly-Linked List in Java.

Every element is a Node.

Each Node holds:
Data (the element).
Pointer to NEXT node.
Pointer to PREVIOUS node.

Structure:

NULL ← [A] ↔ [B] ↔ [C] ↔ [D] → NULL
       head                    tail

head = pointer to first node.
tail = pointer to last node.

LinkedList implements:

List<E> (ordered, index-based access).
Deque<E> (double-ended queue — add/remove from both ends).
Queue<E> (FIFO operations).
Cloneable, Serializable.

2. Internal Node Structure

private static class Node<E> {
    E item;           // The actual element
    Node<E> next;     // Pointer to next node
    Node<E> prev;     // Pointer to previous node

    Node(Node<E> prev, E element, Node<E> next) {
        this.item = element;
        this.next = next;
        this.prev = prev;
    }
}

LinkedList class fields:

public class LinkedList<E> {
    transient int size = 0;
    transient Node<E> first; // Head
    transient Node<E> last;  // Tail
}

3. Core Operations — Internal Implementation

add(E element) — Add to tail:

void linkLast(E e) {
    final Node<E> l = last;
    final Node<E> newNode = new Node<>(l, e, null);
    last = newNode;
    if (l == null) {
        first = newNode; // List was empty
    } else {
        l.next = newNode; // Link previous tail to new node
    }
    size++;
}

O(1) — Just update tail pointer and one link.

addFirst(E element) — Add to head:

void linkFirst(E e) {
    final Node<E> f = first;
    final Node<E> newNode = new Node<>(null, e, f);
    first = newNode;
    if (f == null) {
        last = newNode; // List was empty
    } else {
        f.prev = newNode; // Link previous head to new node
    }
    size++;
}

O(1) — Just update head pointer and one link.

add(int index, E element) — Insert at position:

// MUST traverse to position first: O(n)
Node<E> node = node(index); // Traverse to find node at index
linkBefore(element, node);

node(int index) — THE KEY PERFORMANCE METHOD:

Node<E> node(int index) {
    if (index < (size >> 1)) {
        // Index in first half — traverse from head
        Node<E> x = first;
        for (int i = 0; i < index; i++) x = x.next;
        return x;
    } else {
        // Index in second half — traverse from tail (optimization!)
        Node<E> x = last;
        for (int i = size - 1; i > index; i--) x = x.prev;
        return x;
    }
}

Still O(n) — traverse up to n/2 steps.

get(int index):

return node(index).item; // O(n) traversal!

THIS is why LinkedList random access is O(n).

remove(int index):

// 1. Find node: O(n)
Node<E> x = node(index);
// 2. Unlink: O(1)
unlink(x);

unlink(Node<E> x):

E unlink(Node<E> x) {
    final E element = x.item;
    final Node<E> next = x.next;
    final Node<E> prev = x.prev;

    if (prev == null) {
        first = next; // x was head
    } else {
        prev.next = next; // Skip x from previous
        x.prev = null;    // Help GC
    }

    if (next == null) {
        last = prev; // x was tail
    } else {
        next.prev = prev; // Skip x from next
        x.next = null;    // Help GC
    }

    x.item = null; // Help GC — nullify item
    size--;
    return element;
}

O(1) once position is found.

4. LinkedList as Deque

LinkedList implements Deque — all operations available:

Operation         | Method
──────────────────┼──────────────────────
Add to head       | addFirst(), offerFirst(), push()
Add to tail       | addLast(), offerLast(), add()
Remove from head  | removeFirst(), pollFirst(), poll(), pop()
Remove from tail  | removeLast(), pollLast()
Peek at head      | peekFirst(), peek(), getFirst()
Peek at tail      | peekLast(), getLast()

LinkedList as Stack (LIFO):

Deque<Integer> stack = new LinkedList<>();
stack.push(1);  // addFirst
stack.push(2);
stack.push(3);
stack.pop();    // removeFirst → 3
stack.peek();   // peekFirst → 2

Better alternative: ArrayDeque (faster, less memory).

LinkedList as Queue (FIFO):

Deque<String> queue = new LinkedList<>();
queue.offer("first");   // addLast
queue.offer("second");
queue.offer("third");
queue.poll();           // removeFirst → "first"

Better alternative: ArrayDeque (faster, less memory).

remove(index)          | O(n)       | O(n) (shift)

contains               | O(n)       | O(n)
size                   | O(1)       | O(1)

6. Memory Overhead

ArrayList:

Array of object references.
Each element: 1 reference (8 bytes on 64-bit JVM).
Low overhead.

LinkedList:

Each element: A Node object.
Node: item reference + prev pointer + next pointer + object header.
~40 bytes per node on 64-bit JVM!

1 million element comparison:

ArrayList: ~8 MB (references only) + object storage
LinkedList: ~40 MB (all nodes) + object storage

5x more memory for LinkedList!

7. CPU Cache Behavior (CRITICAL Performance Difference)

This is why ArrayList wins even for "random insertion" in practice.

ArrayList (array-backed):

Elements stored in CONTIGUOUS memory.
CPU cache loads multiple elements at once (cache line = 64 bytes = 8 references).
Cache hit rate: Excellent.
Traversal: Lightning fast due to cache prefetching.

LinkedList (pointer-based):

Nodes scattered in heap (different memory locations).
Each node requires separate cache lookup.
Cache miss: Every node access potentially misses cache.
Traversal: Slow despite O(1) pointer following.

Real benchmark:

Iterate 10,000,000 elements:
ArrayList: ~5ms
LinkedList: ~80ms (16x slower! Due to cache misses)

8. When SHOULD You Use LinkedList?

Honest answer: Almost never in modern Java.

The few valid cases:

1. Frequent insertions/deletions at BOTH ends with no random access needed.
   → Even then, ArrayDeque is better!

2. You explicitly maintain an Iterator position and insert/delete using the iterator.

ListIterator<String> it = list.listIterator(5); // O(n) to position
// Then multiple inserts at this position:
it.add("new1"); // O(1)
it.add("new2"); // O(1)
it.add("new3"); // O(1)

3. Very large list where frequent head removal is needed.
   → Even then, ArrayDeque is better.

In practice: Use ArrayDeque for double-ended queue needs.

9. ListIterator — The Right Way to Use LinkedList

If you must use LinkedList with inserts, use ListIterator:

LinkedList<String> list = new LinkedList<>(existingList);
ListIterator<String> it = list.listIterator();

while (it.hasNext()) {
    String item = it.next();
    if (item.equals("target")) {
        it.add("inserted"); // O(1) — no traversal!
        it.remove();        // O(1) — no traversal!
    }
}

Iterator maintains current position → O(1) insert/delete at current position.
But iterator positioning itself requires traversal → O(n) initially.

10. Real-World Verdict

After understanding internals, the verdict:

Situation                           | Use
────────────────────────────────────┼──────────────
General list                        | ArrayList
Frequent end insertions/deletions   | ArrayDeque
Random access (get by index)        | ArrayList
Iteration + modification            | ArrayList with removeIf()
Thread-safe list (rare writes)      | CopyOnWriteArrayList
FIFO queue                          | ArrayDeque (not LinkedList)
LIFO stack                          | ArrayDeque (not Stack)
Sorted list                         | TreeSet / PriorityQueue

LinkedList has almost no competitive advantage in modern Java due to CPU cache effects.

11. ₹5 Crore Interview Answer

Interviewer:

"How does Java LinkedList work internally? When would you prefer it over ArrayList?"

5 Crore Answer:

Java's LinkedList is a doubly-linked list — each Node contains the element, a reference to the next node, and a reference to the previous node. The class maintains head (first) and tail (last) references, enabling O(1) insertion and deletion at both ends.

For insertion at an arbitrary index: LinkedList must traverse the list to find the position — O(n/2) average. Then the actual link manipulation is O(1). For get(index): same O(n) traversal — this is the critical performance bottleneck.

The implementation has one optimization: it checks which half the index falls in and traverses from either the head or tail — reducing the maximum traversal to n/2 rather than n.

LinkedList also implements Deque, making it usable as a stack or queue. However, ArrayDeque consistently outperforms LinkedList for both use cases — it's a resizable circular array, with O(1) amortized operations at both ends and much better cache behavior.

The decisive performance difference is CPU cache behavior. ArrayList stores elements in a contiguous array — when traversing, the CPU's cache prefetcher loads upcoming elements proactively. Each cache line (64 bytes) holds 8 references — sequential access is extremely fast.

LinkedList nodes are allocated individually in the heap, potentially far apart in memory. Every node access may cause a cache miss — requiring a main memory access (100ns vs 1ns for cache). In practice, iterating 10 million elements in LinkedList can be 10-20x slower than ArrayList despite both being O(n).

Additionally, LinkedList has ~5x higher memory overhead per element — each node has three fields plus object header, typically 40 bytes versus ArrayList's 8-byte reference.

Honestly, in modern Java, LinkedList is rarely the right choice. ArrayDeque replaces it for queue/stack use cases. ArrayList with iterator-based removeIf() handles modification-during-iteration. If truly needed (Iterator-based mid-list insertion with maintained position), use ListIterator to avoid repeated traversals.
